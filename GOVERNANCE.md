# Project Governance

This document outlines the governance model for the **Circle** project. It describes how decisions are made, how roles are defined, and how the community interacts.

## 1. Overview
The Circle project is a community-driven initiative. We believe in transparency, consensus, and respectful collaboration.

## 2. Roles and Responsibilities

### 2.1 Contributors
Anyone who contributes to the project by submitting code, documentation, or participating in discussions.
*   **Rights**: Can submit PRs, open issues, and participate in community discussions.
*   **Responsibilities**: Must adhere to the Code of Conduct.

### 2.2 Maintainers
Contributors who have been granted write access to the repository.
*   **Rights**: Merge PRs, manage issues, release new versions.
*   **Responsibilities**: Review code, guide contributors, ensure project quality.

### 2.3 Project Leads / Admins
The core team responsible for the strategic direction of the project.
*   **Rights**: Final say on architectural decisions, governance changes, and maintainer appointments.

## 3. Decision Making Process

### 3.1 Consensus Seeking
We aim for consensus on all technical and non-technical decisions. Discussions should happen publicly on GitHub Issues or Discussions.

### 3.2 Voting
In cases where consensus cannot be reached, the Maintainers may vote. A simple majority is usually sufficient, but significant changes may require a supermajority.

## 4. Code Review Process
All changes must go through a Pull Request review process.
*   At least one approval from a Maintainer is required for merging.
*   CI/CD checks must pass.

## 5. Amendment
This governance model can be amended by a vote of the Project Leads.

## 6. Contact
For questions regarding governance, please contact the maintainers via the [Support channels](./SUPPORT.md).
